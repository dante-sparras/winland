# Clean architecture in four layers

Winland's source is four layers, and each project references only the layers inside it.

- `Winland.Domain` is the model and its rules: Clients, Workspaces, Monitors, Layouts, Motions, decorations, binds and the config language. It references no project and no package.
- `Winland.Application` runs every input and command as one step through the `WindowManager`, and owns the command protocol and the event stream. It references Domain. The interfaces in its `Ports` folder are what an outer layer implements for it.
- `Winland.Infrastructure` is the Windows adapter. It feeds OS events in, applies each `Outcome` with Win32 calls generated by CsWin32, and hosts the IPC pipe. `Winland.Install` is in the same layer and handles install, update and the logon task.
- `Winland.Daemon` and `Winland.Ctl` are the presentation layer. The daemon is the `winland` process and wires the other layers together. `Winland.Ctl` builds `winlandctl`, which references only Application, so it stays a small executable without the Windows SDK.

Each of those projects has its own test project, and the solution folders are numbered in this order.

Layouts and config are pure algorithms, and Win32 work (hooks, `SetWindowPos`) can't be unit-tested. With every Win32 call outside Domain and Application, those two are tested with plain unit tests and no real windows. The project references make the compiler enforce the direction, so an inner layer cannot reach an outer one by accident.
