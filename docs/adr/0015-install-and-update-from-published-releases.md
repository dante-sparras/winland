# Winland is installed by one command and updated by `winland update`

A user installs Winland by running one PowerShell line, `irm https://raw.githubusercontent.com/dante-sparras/winland/main/scripts/install.ps1 | iex`. The script asks two questions: whether to start Winland when you sign in, and whether to start it now. Enter means yes. It downloads `Winland-win-x64.zip` and `SHA256SUMS` from the newest published release, refuses a zip whose hash does not match, and runs `winland install` for every user, with `--no-logon` or `--no-start` for a no. It always turns off Snap and the touchpad swipes (ADR 0014). Run again on a machine where Winland is installed, it asks nothing and updates.

There are two channels. Stable is the newest published release, and the one-line install starts on it. The same script run with `-Channel dev` installs dev. Dev is one rolling prerelease on the tag `dev`, rebuilt from `main` after CI passes on each commit there, with a version such as `0.1.0-dev.42+439da64`. `winland update --channel stable` or `--channel dev` switches, and Winland remembers the choice in `%USERPROFILE%\.winland`. Switching from dev to stable installs the newest stable release even when it is older.

`winland update` reads the release of the chosen channel, stops when Winland already runs that build, and otherwise downloads and checks the zip, stops Winland, replaces the installed files, and starts the new version. On stable that means a newer version, and on dev a different commit. The config is kept. Winland never checks for updates by itself. The zip on the release page and `winland install` stay for installing by hand.

Downloading a zip, finding the right folder and running a command from it was too many steps for a first try. A script fetched by PowerShell gets no download mark, so the unsigned build passes without the SmartScreen warning, and the checksum still holds it to what the release published. Building from source like a git-based installer would need git and the .NET SDK on every machine. A dev channel is built by CI instead, from commits that already passed it, so testers can follow `main` without a toolchain. The installer does not ask about it, because a new user should not have to choose. A tester runs the dev line instead. The script does not offer a per-user install either. Winland arranges administrator windows such as Task Manager only when it runs elevated, and `winland install --user` stays for installing by hand.
