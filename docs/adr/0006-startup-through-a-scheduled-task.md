# Winland installs itself and starts at logon

`winland install` asks for one UAC approval, stops a running Winland, copies `winland` and `winlandctl` into `C:\Program Files\Winland`, and registers a scheduled task that runs that copy at logon with the highest privileges. The task never starts the folder install was run from. The install folder is added to the machine `PATH`, a Start menu shortcut carries Winland's AppUserModelID, and Settings › Apps uninstalls by running `winland uninstall`. Winland then starts, and from then on it starts at logon without a prompt. `winland install --user` asks for no approval. It copies Winland into `%LOCALAPPDATA%\Programs\Winland`, adds that folder to the user `PATH`, and starts it at logon from the user's Run key, unelevated and without a prompt. The Start menu shortcut and the Settings › Apps entry are per-user, and a Winland started from that copy never relaunches itself through UAC. `winland uninstall` stops Winland and removes the task or the Run key entry, the shortcut, the Settings › Apps entry, the `PATH` entry and the installed files, and keeps the config; `--purge` also removes the config, the logs and the state.

The Run key and Startup folder can't start an elevated program silently, and a Windows service runs in session 0, where it can't touch the user's windows. The elevated task must start a file only administrators can change, or any program the user runs could replace what it starts, so the install puts Winland under Program Files itself instead of asking the user to copy it there.
